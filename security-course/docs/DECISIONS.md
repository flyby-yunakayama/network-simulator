# 設計判断記録

この文書は、実装だけから推測しにくい重要判断を残します。新しい判断は、`ADR-XXX` の連番で追加します。

## ADR-001：次期教材を既存リポジトリ内のサブプロジェクトとして開始する

- **状態**：採用、将来再検討
- **状況**：前作との接続を保ちつつ、次作の試作速度を上げたい。
- **判断**：最初の原型は `security-course/` に置き、前作の `sec*` を変更しない。
- **理由**：前作資産との関係を明示でき、移行前に教材仮説を検証できる。
- **結果**：ライセンスや公開単位の最終判断は未確定。規模・販売条件が固まった時点で別リポジトリ化を再検討する。

## ADR-002：実行の正本を共通コア、学習差分をNotebook・原稿に分ける

- **状態**：採用
- **状況**：前作の章別コード複製は学習上有効だが、複数エージェントによる保守では修正漏れが起きやすい。
- **判断**：次作の実行可能コードは共通コアへ集約し、章で見せる差分は教材側で管理する。
- **理由**：テスト、修正、出典、結果の一貫性を保ちやすい。
- **結果**：必要な場合だけ、明示的な教材スナップショットを生成する。

## ADR-003：最初の垂直スライスにARPスプーフィングを選ぶ

- **状態**：採用
- **状況**：前作との接続、視覚的な状態変化、検知と防御の対比を一章で検証したい。
- **判断**：SEC-04を最初の原型とする。
- **理由**：ARPキャッシュ、偽装主張、中継、競合検知、バインディング防御を小さなモデルで表現できる。
- **結果**：SEC-01/SEC-02の共通化はSEC-04の公開結果を保ちながら後から行う。

## ADR-004：攻撃は同期・インメモリの状態遷移として表現する

- **状態**：採用
- **状況**：実パケットを扱わず、安全かつ決定的に学習したい。
- **判断**：`SimulatedLan` がPythonオブジェクトを同期配送する。
- **理由**：外部環境差を排除し、イベント列を完全にテストできる。
- **結果**：遅延、競合、タイムアウトなどは現モデルでは省略し、必要な章で明示的に追加する。

## ADR-005：検知と防御を別の構成要素にする

- **状態**：採用
- **状況**：アラートを出すことと状態変更を拒否することは、教育上も実装上も異なる。
- **判断**：`ArpConflictDetector` と `StaticBindingGuard` を分ける。
- **理由**：検知だけでは攻撃を止めないこと、防御だけでは観測能力を保証しないことを比較できる。
- **結果**：今後のIDS/IPS章でも、観測・判断・制御の責務を分ける。

## ADR-006：本文に載せる結果は安定した結果オブジェクトから取得する

- **状態**：採用
- **状況**：print出力や内部属性へNotebook・原稿が依存すると、実装変更で教材が壊れる。
- **判断**：各シナリオは `ScenarioResult` 相当を返し、`summary()` と `event_rows()` を提供する。
- **理由**：テスト、Notebook、原稿で同じ事実を共有できる。
- **結果**：公開フィールド変更は教材全体へ影響するため、互換性レビューを行う。

## ADR-007：ランタイム依存をゼロから開始する

- **状態**：採用
- **状況**：Colab導入、安全境界、再現性を簡潔に保ちたい。
- **判断**：SEC-04のランタイムはPython標準ライブラリだけで実装する。
- **理由**：教材の中心は状態遷移であり、外部パッケージは不要。
- **結果**：可視化やデータ処理の依存は、共通需要が明確になってから追加する。
