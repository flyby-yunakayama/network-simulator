# プロジェクト計画 — Pythonで攻防しながら学ぶネットワークセキュリティ

## 1. 文書の位置づけ

この文書は、講座・Colab教材・書籍を一つの教育プロダクトとして開発するための企画正本です。章ごとの詳細要件は `specs/`、技術設計は `ENGINEERING.md`、執筆規約は `WRITING.md` を正本とします。

## 2. プロダクト仮説

前作では、ネットワークが正常に動く仕組みをPythonシミュレータで段階的に実装しました。次作では、その正常動作が置いている信頼の前提を意図的に崩し、次の一連の判断を学びます。

> 正常系を観測する → 攻撃の成立条件を作る → 痕跡を検知する → 防御を実装する → 効果と副作用を測る → 現実との差を説明する

本企画の価値は「攻撃コマンドを覚えること」ではなく、プロトコル、状態、ログ、指標を結び付けて、防御設計を説明できるようになることです。

## 3. 想定読者

中心読者は、Pythonの関数・クラス・辞書を読めるネットワーク初学者です。

- 前作の講座または書籍を修了し、次の学習テーマを探している人
- セキュリティを学びたいが、Kali Linux、仮想環境、実ネットワーク操作にはまだ不安がある人
- ネットワーク、クラウド、バックエンドを学び始めた学生・若手エンジニア
- 用語暗記ではなく、状態遷移とログから理解したい資格学習者
- 授業や研修で、安全に再現できる演習を必要とする教員・講師

前作は推奨前提ですが必須にはしません。各章で必要な正常系を短く復習し、より詳しい説明を前作へ案内します。

## 4. 到達目標

全体を修了した学習者は、次を実行・説明できる状態を目指します。

1. 資産、脅威、脆弱性、攻撃、リスク、防御を区別する。
2. 攻撃をプロトコルの信頼前提と状態遷移に結び付けて説明する。
3. 正常通信と攻撃通信を同じイベントモデルで観測する。
4. 検知と防御を別の機能として実装し、役割の違いを説明する。
5. 攻撃成功率だけでなく、正常通信成功率、遅延、誤検知、可用性を測る。
6. ログからインシデントのタイムラインと原因を再構成する。
7. 教材モデルで省略した現実の条件を指摘し、断定しすぎない。
8. 最終演習で、小規模ネットワークの防御案と評価結果を報告する。

## 5. プロダクト原則

### 5.1 動かしてから説明する

抽象概念だけを先に並べず、正常系の小さな実験、状態の変化、結果の比較を学習の中心に置きます。

### 5.2 攻撃と防御を対にする

攻撃だけを独立した見世物にしません。各攻撃章には、観測、検知、予防または緩和、正常通信への副作用を含めます。

### 5.3 閉じたシミュレータだけを使う

教材コードは実ネットワークへ送信せず、Pythonオブジェクトの状態遷移だけで完結します。安全境界の詳細は `SAFETY_AND_PROVENANCE.md` を参照してください。

### 5.4 再現できる結果だけを教材へ載せる

本文やNotebookで示す数値は、公開APIとテストから再現できる値に限定します。乱数を使う場合はシードと条件を記録します。

### 5.5 「教材上のモデル」と「現実」を分ける

簡略化は教育上必要ですが、簡略化した事実を隠しません。各章で、示せたこと、示していないこと、実環境で追加確認が必要なことを明示します。

## 6. 媒体ごとの役割

同じ説明を複製せず、媒体の強みを分けます。

| 媒体 | 主な役割 | 含めるもの | 避けるもの |
|---|---|---|---|
| Colab | 実験と改造 | 実行セル、観測表、比較、穴埋め課題 | 長い理論説明、未検証コード |
| Udemy | 動きと判断の解説 | イベント列の読み方、ライブ実装、失敗例、デバッグ | 完成コードの読み上げ |
| 書籍 | 原理と体系化 | 信頼前提、成立条件、設計判断、現実との差、章末問題 | 動画と同じ逐語説明 |
| GitHub | 再現性と更新 | コード、テスト、Notebook、正誤、仕様、出典 | 出典のない外部事実 |

## 7. スコープ

### 対象

- イーサネット、ARP、DHCP、DNS、IP、TCP、基本的な認証・完全性・TLSの教育モデル
- 攻撃前後の状態、ログ、指標の比較
- 競合検知、ルール、レート制限、状態追跡、暗号学的検証の概念モデル
- 小規模な単一LANまたは明示的に構成した仮想トポロジ
- Python 3.11以上とGoogle Colabで実行できる教材

### 対象外

- 実パケットの送信、取得、注入、改ざん
- 実ホストの探索、スキャン、脆弱性検査、負荷試験
- OSやクラウド環境の設定変更
- 特定製品の運用手順、回避手法、永続化、痕跡消去
- マルウェア、資格情報窃取、実用的なエクスプロイト
- 暗号アルゴリズムの独自実装を安全な実装として推奨すること

## 8. カリキュラム

章IDは `catalog.json` と一致させます。順序は開発順ではなく、学習順です。

| 章 | 主題 | 中心となる実験 | 主な評価軸 |
|---|---|---|---|
| SEC-00 | 全体像と安全境界 | 資産・脅威・防御を一つのシナリオへ分類 | 説明の正確さ |
| SEC-01 | セキュリティ対応シミュレータ | 攻撃者・防御者・センサー・イベントを実装 | 再現性、追跡可能性 |
| SEC-02 | 通信の観測 | 正常系ログからベースラインを作る | 完全性、集計の妥当性 |
| SEC-03 | MACフラッディング | MACテーブル容量を超える主張を生成 | 露出通信、正常転送率 |
| SEC-04 | ARPスプーフィング | 偽装主張で中継位置を作り、防御と比較 | 検知数、拒否数、可用性 |
| SEC-05 | DHCPへの攻撃 | アドレス枯渇と不正設定配布を分離して再現 | 正常割当率、信頼境界 |
| SEC-06 | DNS偽装 | 複数応答の競争とキャッシュ採用を比較 | 誤解決率、検証結果 |
| SEC-07 | IP偽装とフラグメント | 送信元偽装と再構成方針の差を観測 | 受理率、再構成結果 |
| SEC-08 | TCPへの攻撃 | 半開き接続でバックログを消費 | 接続成功率、資源使用量 |
| SEC-09 | DoSとレート制限 | 送信源・時間窓別の制限を比較 | 遮断率、正常遅延、公平性 |
| SEC-10 | ファイアウォール | ルール順序と状態追跡を実験 | 許可・拒否、ルール到達 |
| SEC-11 | IDS・IPS | シグネチャとベースライン逸脱を比較 | 真陽性、偽陽性、見逃し |
| SEC-12 | 認証とリプレイ | 同じ認証メッセージの再送とNonceを比較 | 不正受理率、再利用拒否 |
| SEC-13 | 完全性とメッセージ認証 | 改ざん後のハッシュ・HMAC・署名検証 | 検証成功、鍵の前提 |
| SEC-14 | PKI・証明書・TLS | 検証省略時と証明書検証時の中間者状態を比較 | 相手認証、失敗理由 |
| SEC-15 | 総合演習 | 小規模企業ネットワークで複数事象へ対応 | 可用性、検知時間、誤検知、説明 |

## 9. 章の標準成果物

一章を「実装済み」と呼ぶには、原則として次が必要です。

- 章仕様：学習目標、脅威モデル、要件、受入条件
- シミュレータ：正常系、攻撃系、検知、防御、結果オブジェクト
- テスト：挙動、再現性、安全境界、回帰
- Colab Notebook：説明、実験、比較、演習、現実との差
- 書籍原稿：原理、解釈、設計判断、章末問題
- 出典：外部事実を支える一次資料・公式資料
- 追跡表：要件からコード・テスト・教材への対応
- 動画台本またはレクチャーマップ：書籍・Notebook完成後に作成

## 10. 状態定義

`catalog.json` の `status` は次の意味で使います。

| 状態 | 意味 |
|---|---|
| `planned` | タイトルと学習目標だけがある |
| `specified` | 仕様と受入条件がレビュー可能 |
| `prototype` | 一つ以上の実行可能な垂直スライスがあり、教材仮説を検証できる |
| `draft` | 章の標準成果物が一通りそろっている |
| `review` | 技術・教育・編集・安全レビュー中 |
| `ready` | 公開候補としてすべてのゲートを通過した |

状態を進めるPRでは、成果物の存在だけでなく受入条件の充足を確認します。

## 11. 開発ロードマップ

### M0：基盤とSEC-04原型

成果物：AI作業規約、章台帳、仕様・原稿テンプレート、CI、安全境界、ARP攻防の垂直スライス。

終了条件：クリーン環境でテストと検証が通り、防御なし・防御ありの差をNotebookと原稿から説明できる。

### M1：観測基盤の共通化

対象：SEC-01、SEC-02。

成果物：汎用イベント型、フェーズ、メトリクス、比較表、シナリオメタデータ、Notebook表示ヘルパー。

終了条件：SEC-04が汎用基盤へ移行しても公開結果が変わらず、次章が同じ部品を再利用できる。

### M2：レイヤ2・名前解決のMVP

対象：SEC-03〜SEC-06。

終了条件：MAC、ARP、DHCP、DNSの四章が同じ観測・評価方式を使い、章間の用語と実装が整合する。

### M3：可用性と境界制御

対象：SEC-07〜SEC-11。

終了条件：TCP、DoS、ファイアウォール、IDS/IPSを横断して、真陽性・偽陽性・正常通信影響を比較できる。

### M4：認証・完全性・TLS

対象：SEC-12〜SEC-14。

終了条件：認証、完全性、相手認証の違いを、同じメッセージモデルと検証結果で説明できる。

### M5：総合演習と出版準備

対象：SEC-15、全章編集。

終了条件：総合シナリオ、解答例、技術監修、出典監査、動画レクチャーマップ、公開用Notebook、正誤・更新方針がそろう。

## 12. 企画検証

制作量を増やす前に、SEC-04を使って次を検証します。

- 初学者が正常系、攻撃成立、検知、防御の違いを説明できるか
- 「仮想環境不要」「実ネットワーク不使用」が参加障壁を下げるか
- Notebookの完遂率と、演習で変更できた項目
- 書籍の説明と動画の補足が重複していないか
- 前作未受講者に必要な復習量
- 攻撃の刺激性ではなく、防御判断に価値を感じるか

測定項目は、再生数だけでなく、Notebook完遂、課題回答、誤概念、継続意向を含めます。

## 14. 著者判断が必要な事項

AIエージェントは次を自動決定しません。

- 既存リポジトリ内で継続するか、別リポジトリへ分離するか
- CC BY-SA 4.0を継続するか、コードと原稿でライセンスを分けるか
- 最終タイトル、出版社、価格、商標、販売条件
- 実環境演習を将来追加するかどうか
- 公開APIの互換性を破る大規模な再設計

それ以外の安全で可逆な変更は、仕様ID、テスト、小さなPRによって進めます。
