# 安全境界・倫理・出典管理

## 1. 基本方針

本プロジェクトは、ネットワーク攻撃の仕組みを防御設計へ結び付けて学ぶための**閉じた教育用シミュレータ**です。実ネットワークで利用できる攻撃ツールの開発、配布、手順化は目的に含みません。

安全性は、注意書きだけでなく、設計、依存関係、テスト、レビュー、教材表現の各層で守ります。

## 2. 守る対象

- 学習者や第三者のネットワーク、端末、アカウント、データ
- 著者・共同作業者の秘密情報と個人情報
- 前作・次作の著作権、ライセンス、出典の追跡可能性
- 講座・書籍の技術的信頼性
- AIエージェントが自律作業しても越えてはならない境界

## 3. 許可される活動

- インメモリのパケット、フレーム、キャッシュ、キュー、接続状態
- 決定的なイベント列と架空トポロジ
- 正常系、攻撃系、検知、防御の比較
- 架空のIPアドレス、MACアドレス、ドメイン、認証情報、証明書
- ローカルな一時ファイルへの教材データ出力
- RFC、標準、公式文書に基づく説明
- 防御の効果、誤検知、性能・可用性への副作用の評価

## 4. 禁止される活動

- 実パケットの送信、注入、盗聴、改ざん
- raw socket、Scapy、pcap取得、ネットワークインターフェース操作
- ポートスキャン、サービス列挙、脆弱性探索
- OSのARP、DNS、ルーティング、ファイアウォール、証明書ストアの変更
- 外部ホストへのDoS、負荷試験、リレー、プロキシ
- 資格情報、Cookie、トークン、鍵、個人データの取得・保存
- 回避、永続化、権限昇格、痕跡消去、マルウェア化
- 実環境の対象選定や攻撃を自動化するコード
- 「教育用」と記すだけで、実用可能性を残した攻撃実装

禁止機能が必要に見える章は、実機能を追加せず、Pythonオブジェクトの状態遷移へ置き換えます。

## 5. 安全レビューの区分

### S0：説明だけ

概念、脅威モデル、図解。外部操作なし。通常レビューで可。

### S1：閉じた状態遷移

インメモリの攻撃・検知・防御。現在の標準。仕様、テスト、安全境界レビューが必要。

### S2：外部I/Oを伴うが攻撃性のない機能

例：公開データセット読込、ファイル生成。必要性、URL、ライセンス、秘密情報の有無をレビューする。既定では教材へ埋め込んだ小さなデータを優先する。

### S3：実ネットワークまたはOS状態へ触れる機能

本プロジェクトでは禁止。別企画として著者が安全方針を明示的に変更しない限り実装しない。

## 6. 技術的ガード

- ランタイム依存を標準ライブラリ中心にする。
- 禁止importを `tests/test_safety_boundary.py` で検査する。
- CIは外部サービスや秘密情報なしで完了させる。
- Notebookへ認証セル、Driveマウント、APIキー入力を入れない。
- シナリオ関数は外部I/Oをせず、結果オブジェクトを返す。
- 架空のアドレスとペイロードを使う。
- 外部アクセスが必要な開発スクリプトを、ランタイムパッケージへ置かない。

静的検査は完全な証明ではありません。レビューでは、動的import、標準ライブラリ経由の通信、外部コマンド、ファイル副作用も確認します。

## 7. 教材表現のガード

- 実ネットワークでの実行を勧めない。
- 攻撃のコマンド列、対象探索、運用回避を掲載しない。
- 攻撃成立条件と同じ分量以上で、観測・検知・防御・限界を扱う。
- 防御機能を「完全な安全」と表現しない。
- 製品固有の機能名を一般概念の代わりに使わない。
- 実環境との差を各章で明示する。
- 学習者の変更課題も、シミュレータ内部に限定する。

## 8. データと秘密情報

- 実在する組織、人物、ドメイン、内部IP、認証情報を教材データへ使わない。
- Notebook出力、ログ、スクリーンショットをコミットする前に秘密情報を確認する。
- CIへ不要な秘密情報を登録しない。
- 学習者の入力を収集する仕組みをリポジトリへ実装しない。
- 調査メモに個人情報が含まれる場合、公開リポジトリへ保存しない。

## 9. 出典台帳

外部事実は `references/sources.json` へ登録します。各項目は少なくとも次を持ちます。

- 一意の `id`
- `title`
- 発行主体 `publisher`
- `url`
- 資料種別 `type`
- 参照日 `accessed`
- 使用章 `chapters`
- 何の根拠に使うかを示す `notes`

本文、仕様、Notebookではsource IDを使い、URLの正本を一か所に集約します。更新され得る資料は、章レビュー時に再確認します。

## 10. コードと文章の由来

### 前作から再利用する場合

- 元ファイルとコミットまたはタグを記録する。
- 変更点をPRへ記載する。
- 既存ライセンス条件を維持する。
- コピーではなくアダプタで接続できないか先に検討する。

### AI生成・支援

- AIエージェントが作成したコード・文章も、人間が正確性、安全性、出典、権利をレビューする。
- AIの出力を出典として扱わない。
- 出典不明の引用、固有表現、コード断片をそのまま採用しない。
- 生成物の責任主体は、最終的にレビュー・公開するプロジェクト側にある。

### 外部コード・図・データ

- ライセンス、著作者、URL、改変条件を記録する。
- ライセンスが不明なものは使わない。
- 教材の中核コードは、外部攻撃ツールからコピーしない。
- 図は自作または再生成可能な形式を優先する。

## 11. ライセンス上の留意点

現リポジトリはCC BY-SA 4.0を掲げています。この基盤は、その状態を変更しません。

書籍原稿、ソフトウェアコード、Notebookを同一ライセンスで公開し続けるか、別リポジトリやデュアルライセンスへ分けるかは事業・法務上の判断です。AIエージェントは、明示的な著者判断なしに次を行いません。

- `LICENSE` の変更
- 新しいライセンスファイルの追加による条件変更
- 著作権表記の変更
- 外部素材の条件と矛盾する再配布

公開前に、出版社との契約条件を含めて人間が確認します。本節は法的助言ではなく、判断を見落とさないためのプロジェクト規約です。

## 12. 依存関係の来歴

新しい依存を追加するPRでは、次を記録します。

- 何に必要か
- 標準ライブラリや小さな自作で代替できない理由
- ライセンス
- メンテナンス状況と対応Python版
- 外部通信、OS操作、ネイティブコードの有無
- Colabでの導入方法
- 依存を削除した場合の影響

攻撃・パケット操作を主目的とする依存は、使う機能が安全でも原則採用しません。

## 13. 安全インシデント時の対応

実ネットワーク機能、秘密情報、権利不明素材が誤って含まれた場合は、通常の機能修正より優先します。

1. 公開範囲と影響を確認する。
2. 該当変更を無効化または削除する。
3. 秘密情報なら失効・更新する。
4. 履歴からの削除が必要か、人間が判断する。
5. 原因と再発防止を設計判断またはテストへ反映する。
6. 関連する教材・リリースへ訂正を出す。

## 14. 章・リリースの安全チェック

- [ ] すべての攻撃がインメモリ状態遷移である。
- [ ] 実ネットワーク、OS、外部コマンドへ触れない。
- [ ] 架空のデータだけを使う。
- [ ] 攻撃と対になる検知・防御・限界がある。
- [ ] Notebookに出力、認証情報、個人情報がない。
- [ ] 外部事実が出典台帳へ登録されている。
- [ ] 外部コード・図・データのライセンスを確認した。
- [ ] 依存関係の安全性とライセンスを確認した。
- [ ] 既存ライセンスを意図せず変更していない。
- [ ] 安全境界テストと通常テストが通る。
