# 出典台帳の使い方

`references/sources.json` は、仕様、原稿、Notebookで使う外部事実の正本です。

## ルール

1. 一つの資料に、安定した大文字のsource IDを付けます。
2. 一次資料、標準、公式文書を優先します。
3. `accessed` には最後に内容を確認した日をISO形式で記録します。
4. `chapters` には使用する章IDを列挙します。全体資料は `ALL` を使えます。
5. `notes` には「何の根拠に使うか」を具体的に書きます。
6. 原稿では `[SOURCE-ID]`、仕様ではバッククォート付きsource IDで参照します。
7. URLや資料の版が変わった場合もIDを安易に再利用せず、意味が変わるなら新しいIDを作ります。
8. AIの回答、検索結果の要約、出典不明の二次記事を根拠資料として登録しません。

## 推奨する資料種別

- RFC、標準仕様
- 標準化団体・政府機関の公式文書
- 公式の脅威分類・検知資料
- 原著論文
- 公式製品文書（製品固有の説明に限る）

## 更新手順

1. 公式URLで資料を確認する。
2. 章で使う主張と資料の対応を決める。
3. `sources.json` を更新する。
4. 原稿、仕様、Notebookへsource IDを記す。
5. `docs/TRACEABILITY.md` の外部根拠表を更新する。
6. レビューで、資料が主張を本当に支えているか確認する。

引用文を長く保存せず、要点と使用目的だけを記録します。
